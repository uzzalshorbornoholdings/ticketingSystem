system components categorized by their functional architectural layers:
## 1. Input & Ingestion Layer (Sources)
 * **User Endpoint Portal:** Interface where end-users manually submit issues or requests.
 * **Monitoring & Alerting Tools:** Automated systems (e.g., SIEM, network monitors) that generate system alerts based on anomalies or thresholds.
## 2. Central Processing & Triage Layer
 * **Ticketing UI Dashboard:** The core operational console where incoming items are aggregated, validated, and categorized.
 * **Classification Engine:** Component that splits traffic into three distinct modules:
   * **Incident (INC):** For broken systems or outages.
   * **Service Request (SR):** For routine requests, access, or new assets.
   * **Change Request (CR):** For planned modifications to production environments.
## 3. Operations & Resolution Layer (Teams & Roles)
### 🖥️ IT (Helpdesk / L1 Support)
 * Handles initial user-facing hardware/software troubleshooting and basic fulfillment.
### 🌐 NOC (Network Operations Center)
 * **Network Admin Infrastructure:** Manages switches, routers, firewalls, and network bandwidth stability.
### 🛡️ SOC (Security Operations Center)
 * **Detection Team:** Monitors SIEM alerts, filters out noise, and validates true security incidents.
 * **Incident Response (IR) Team:** Executes active containment, mitigation, and eradication during an active security breach.
 * **Threat Hunter Team:** Proactively searches through logs to discover hidden, sophisticated threats.
### ♾️ QA / DevOps
 * Manages deployment pipelines, application stability, CI/CD health, and software bug testing.
### ⚙️ SYS Admin (System Administration)
 * **Linux Admin:** Manages Linux-based servers and infrastructure environments.
 * **Windows Admin:** Manages Active Directory, Windows Server architectures, and enterprise OS patching.
 * **Mac Admin:** Manages enterprise Apple device configurations and MDM compliance.
## 4. Lifecycle & Workflow Subsystems
### 📋 Service Request (SR) Subsystem
 * **Submission Module:** Interactive service catalog for asset selection.
 * **Manager Approval Gate:** Automated workflow routing requests to authorized managers for sign-off.
 * **Fulfillment Engine:** Dispatches tasks directly to IT or Sys Admins.
 * **Closure Module:** User validation and automatic ticket resolution tracking.
### 🛠️ Change Request (CR) Subsystem
 * **Creation & Risk Profiler:** Assesses the scope and assigns a risk score (Low/Medium/High).
 * **CAB (Change Advisory Board) Review Interface:** Dashboard for stakeholders to evaluate, schedule, and approve production changes.
 * **Implementation & Maintenance Window Scheduler:** Tracks scheduled downtime or maintenance slots.
 * **PIR (Post-Implementation Review) & Rollback Engine:** Verifies success criteria or triggers structured safe rollback scripts if a change fails.
## 5. Dashboard UI Layout Matrix Components
 * **Triage Queue Component:** A real-time, unassigned incoming ticket feed.
 * **Team Queue Filter View:** Custom role-based dashboards (e.g., viewing only *Linux Admin* or *Detection Team* tickets).
 * **SLA Countdown Timers:** Color-coded visual counters mapping resolution deadlines based on ticket priority metrics (P1 to P4).
 * **Request Separation Navigation Tabs:** Top-level UI structural tabs to instantly switch focus between Incidents, SRs, and CRs.
