Issue 1 (ROOT CAUSE): AutoSizeColumnsMode.Fill conflicts with explicit col.Width assignment
CAUTION

This is very likely the primary cause of the crash you are seeing at col.Width = width on line 150.

In 
MainForm.Designer.cs
, all three grids are configured with:

this.gridIncidents.AutoSizeColumnsMode = DataGridViewAutoSizeColumnsMode.Fill;  // Line 291
But in 
MainForm.cs
 
ConfigureGrids()
, we explicitly set column widths:

SetColumnWidth(grid, "ID", 45);      // Line 94
SetColumnWidth(grid, "Priority", 65); // Line 95
When AutoSizeColumnsMode is Fill, WinForms internally manages column widths. Setting col.Width directly causes a conflict during the layout computation cycle, which throws NullReferenceException inside WinForms internal code like ComputeVisibleColumns().

Fix
Inside 
ConfigureGrids
, set AutoSizeColumnsMode to None before modifying widths, then set the Title column (the widest) to Fill so it takes remaining space:

private void ConfigureGrids(DataGridView grid)
  {
      if (grid.Columns.Count == 0) return;
+
+     // Must disable auto-sizing before setting explicit widths
+     grid.AutoSizeColumnsMode = DataGridViewAutoSizeColumnsMode.None;
+
      SetColumnWidth(grid, "ID", 45);
      ...
+     // Let the Title column fill remaining space
+     var titleCol = FindColumn(grid, "Title");
+     if (titleCol != null) titleCol.AutoSizeMode = DataGridViewAutoSizeColumnMode.Fill;

Issue 3: 
Grid_CellFormatting
 uses row.Cells["CreatedAt"] without case-insensitive lookup
On 
MainForm.cs line 431
, the cell lookup pattern:

var createdAtCell = row.Cells["CreatedAt"] ?? row.Cells["createdat"];

This still throws if neither casing matches. Should use the same foreach pattern as 
SetColumnWidth
.

Create a reusable FindCell helper and use it in 
Grid_CellFormatting
 and

Issue 5: 
LoginForm.cs
 schema path resolution
In 
LoginForm.cs line 26
, the path traversal goes up 4 levels (..\..\..\..\docs\schema.sql). From bin\Debug\, only 2 levels up reaches the src\ folder, then one more to the project root. The path needs ..\..\ (2 levels from bin\Debug\ to src\, then .. to project root).

Fix
Change path to @"..\..\..\..\docs\schema.sql" → verify it resolves correctly, or add a second fallback:

if (!File.Exists(schemaPath))
    schemaPath = Path.GetFullPath(Path.Combine(exeDir, @"..\..\docs\schema.sql"));
